# MusicArtPlus — сайт центра искусств

Репозиторий содержит две части:

| Папка | Что это |
|---|---|
| корень (`index.html`, `assets/`) | статическая вёрстка — демо для согласования дизайна |
| `theme/musicartplus/` | **тема WordPress** — рабочая версия сайта |
| `tools/` | генератор статики и сборщики файлов темы |

Статику смотрит заказчик на GitHub Pages, тема ставится на боевой хостинг.
Вёрстка остаётся эталоном дизайна: иконки, шрифты и демо-контент темы
собираются из неё скриптами, чтобы версии не расходились.

**Документация по теме — [theme/musicartplus/README.md](theme/musicartplus/README.md):**
установка, ключ CRM, структура файлов, интеграция с «Моим классом», что и где
редактируется.

## Статическая вёрстка

Без сборщиков и зависимостей: чистые HTML, CSS и ванильный JavaScript.

## Страницы

| Файл | Раздел |
|---|---|
| `index.html` | Главная (9 блоков по ТЗ) |
| `about.html` | О нас |
| `directions.html` | Наши направления + преимущества + FAQ |
| `teachers.html` | Педагоги, приглашённые артисты, фото- и видеоблок, отзывы, форма |

## Как посмотреть

```bash
cd site
python3 -m http.server 8000
# открыть http://localhost:8000
```

Открывать через сервер, а не двойным кликом: карта, видео и модальные окна
требуют http-протокола.

## Дизайн

* **Цвет.** Белый фон и «воздух», акцент — рассветный жёлтый `#F3B71E`,
  чёрный `#12100E` строго дозированно, как графика. Все цвета — CSS-переменные
  в начале `assets/css/style.css` (блок `:root`), меняются в одном месте.
* **Шрифт.** Ysabeau (Google Fonts) + Ysabeau SC для надзаголовков.
  Переносы в заголовках не проставлены руками — за них отвечает `text-wrap: balance`,
  поэтому строки остаются сбалансированными на любой ширине экрана.
* **Логотип.** Из исходного JPG сделаны прозрачные PNG:
  `logo-color.png` (для светлого фона) и `logo-white.png` (для тёмного и подвала).
* **Анимации.** Только CSS-трансформации и прозрачность плюс лёгкие SVG.
  JavaScript лишь переключает классы через `IntersectionObserver` —
  никаких тяжёлых библиотек и вычислений на каждый кадр скролла.
  При `prefers-reduced-motion` анимации отключаются.

## Функционал

* Слайдер первого экрана. Заголовок появляется классическим способом:
  слова по очереди выезжают из-под маски, следом подзаголовок и кнопки.
  Текст h1 лежит в разметке целиком — важно для поиска и работы без JS.
* Слайдеры — на **Swiper 11** (библиотека лежит локально в `assets/vendor/swiper/`,
  без CDN). Разметка обычная: `.slider[data-swiper="имя"]` → `.swiper` → `.swiper-wrapper`
  → `.swiper-slide`; стрелки выносятся в шапку секции через `[data-swiper-nav="имя"]`.
  Наборы настроек (`data-swiper-preset`) описаны в разделе 7 `main.js`.
  Сетки педагогов и приглашённых артистов остаются сеткой на десктопе, а ниже 760 px
  Swiper подключается сам (класс `slider--grid`) — как и просил заказчик:
  3–4 педагога в ряд на компьютере, слайдер на телефоне.
* Карточка педагога в модальном окне: биография, достижения, **расписание по дням**
  и кнопка записи.
* Видео Rutube и локальные ролики открываются в модальном окне, без ухода с сайта.
  Пока плеер Rutube инициализируется (несколько секунд), показывается индикатор
  загрузки, а под окном — запасная ссылка «Открыть на Rutube».
* Фотогалерея с лайтбоксом: клик по снимку открывает его на весь экран,
  листание стрелками, клавишами `←`/`→`, свайпом; закрытие по `Esc`, клику по фону
  или свайпу вниз. Счётчик кадров, предзагрузка соседних. Лайтбокс создаётся
  скриптом только на страницах с галереей — в разметку ничего добавлять не нужно.
  *В ТЗ было «без возможности приближения фотографии при нажатии» — уточнить
  у заказчика, устраивает ли просмотрщик.*
* Аккордеон FAQ, интерактивная Яндекс.Карта.
* Формы: валидация, автоподстановка `+7` и маска телефона, галка согласия на
  обработку персональных данных.
* **Все кнопки записи открывают модальное окно с формой.** Достаточно поставить
  элементу `data-crm` — обработчик навешивается делегированием, поэтому работает
  и на кнопках, созданных скриптом (карточка педагога). Окно подхватывает контекст:
  от кого пришли (`data-crm-name` / `data-crm-photo` или карточка педагога рядом)
  и какое направление (`data-crm-subject`) — показывает это в шапке формы и
  подставляет в выпадающий список. `href` кнопки при этом остаётся ссылкой в CRM:
  если скрипт не отработает, пользователь всё равно попадёт в «Мой класс».
* Страница новости: обложка, текст, кнопки «поделиться» (Telegram, ВКонтакте,
  копировать ссылку), переходы к предыдущей и следующей публикации, блок
  «Читайте также» и CTA.
* Мобильное меню: полноэкранная панель, бургер превращается в крестик,
  пункты с индикатором активного раздела, внизу — кнопка записи, телефон,
  адрес и соцсети. Пока меню открыто, шапка принудительно «светлая»
  (правила прозрачной шапки отключены через `:not(.menu-open)`).
* Адаптив: 1440 / 1080 / 900 / 720 / 480. Горизонтального скролла нет ни на одной странице.
* Прокрутка нигде не «залипает»: горизонтальные ленты каруселей не перехватывают
  колесо мыши (`overflow-y: hidden` + `overscroll-behavior: contain`), а карта
  включается по клику — иначе колесо над ней зумило бы карту вместо страницы.
* Без JS страницы остаются полностью читаемыми (класс `no-js`).

## Что нужно подключить при интеграции

1. **CRM «Мой класс».** Все кнопки записи используют единую точку настройки —
   объект `CRM` в начале `assets/js/main.js`:

   ```js
   var CRM = { base: 'https://app.moyklass.com/', forTeacher: function (slug) {…} };
   ```

   Кнопка педагога передаёт его slug (`ilyina`, `katyukova`, …). Ссылка на CRM
   используется в двух местах: как запасной `href` у кнопок записи и как «открыть
   расписание» в самой форме. Отправка форм сейчас показывает подтверждение;
   место для реального запроса помечено комментарием в разделе 14 `main.js`.

2. **Расписание педагогов** в карточках сейчас demo-данные (атрибут
   `data-schedule` у карточки). После заполнения CRM его нужно тянуть оттуда.

3. **Точка на Яндекс.Карте.** Сейчас карта ищет адрес геокодером. Чтобы метка
   встала точно на запасной вход, нужно собрать карту в конструкторе
   Яндекс.Карт и подставить её ссылку в `iframe` (блок «Как нас найти»).

4. **Ссылки-заглушки `href="#"`** — «Политика конфиденциальности» и «Согласие на
   обработку данных» (3 ссылки). Ждут страниц с текстами.

5. **Яндекс.Метрика, SSL, sitemap** — подключаются при размещении на хостинге.
   Заголовки, `title`, `description` и Open Graph уже прописаны на каждой странице.

## Содержимое: что реальное, а что демо

**Реальное** (из материалов заказчика): все педагоги и приглашённые артисты с
биографиями, 7 отзывов, преимущества, FAQ, контакты, соцсети, фотографии,
ссылки на видео Rutube, упоминание фонда ФОРТЕФОРМА.

**Демо, требует замены** (материалы ещё не переданы):
* Новости — 8 статей с правдоподобными заголовками и текстами (каждая на своей
  странице; в WordPress это записи одного типа, шаблон `news-*.html`).
* Тексты страницы «О нас» — написаны по имеющейся информации, нужна вычитка.
* Расписание педагогов.
* Цифры на первом экране (11 педагогов, 8 направлений, с 3 лет) — проверить.
* Описания направлений (возраст, формат, длительность урока) — проверить.

**Ждём от заказчика:** карточка вокалиста Сергея Кофанова — сетка адаптивная,
он встанет в общий ряд без переделок.

## Как пересобрать страницы

Шапка, подвал и модальные окна одинаковы на всех 13 страницах, поэтому HTML
собирается скриптом `tools/generator.py`:

```bash
cd site
python3 tools/generator.py
```

**Важно:** правки вносите либо в генератор, либо в HTML — но не в оба места,
иначе следующая пересборка перезапишет ручные изменения. Общие блоки
(шапка, подвал, формы) удобнее менять в генераторе, точечную отладку — в HTML.

В конце генератора стоит флаг `DEMO_HOME_ONLY = True`: он снимает с главной
страницы все переходы на другие страницы сайта — это временный режим для
согласования дизайна главной. Поставьте `False` и пересоберите, чтобы вернуть
навигацию.

## Структура

```
site/
├── index.html  about.html  directions.html  teachers.html  news.html
├── news-*.html              # 8 страниц новостей
├── tools/generator.py       # сборка страниц из общих блоков
└── assets/
    ├── css/style.css        # вся вёрстка, 26 пронумерованных блоков
    ├── js/main.js           # 20 независимых модулей
    ├── vendor/swiper/       # Swiper 11.2.10 (js + css), локально
    ├── img/{ui,teachers,guests,gallery}
    └── video/               # ролики пересжаты: 22 МБ → 1.3 МБ
```

Изображения оптимизированы: 129 МБ исходников → ~7 МБ, у всех `loading="lazy"`
кроме первого экрана.
