# Тема MusicArtPlus

Тема WordPress для центра искусств MusicArtPlus. Контент редактируется через
ACF, онлайн-запись передаётся в CRM «Мой класс».

Требования: WordPress 6.0+ (проверено на 7.1), PHP 7.4+ (проверено на 8.4),
Advanced Custom Fields **PRO** 6.8+ (нужны повторители и галерея).

---

## Установка

1. Скопировать папку `musicartplus` в `wp-content/themes/`.
2. Установить и активировать Advanced Custom Fields PRO.
3. Активировать тему.
4. В `wp-config.php` **выше** строки `require_once ABSPATH . 'wp-settings.php';`
   добавить ключ CRM:

   ```php
   define( 'MOYKLASS_API_KEY', 'ключ-из-моего-класса' );
   ```

   Ключ берётся в «Мой класс» → Настройки → API. Образец всех строк —
   в `wp-config-sample-snippet.php`.

5. Открыть **Интеграция с CRM** в админке и нажать **Наполнить сайт** — тема
   создаст страницы, педагогов, направления, отзывы и новости из вёрстки
   вместе с картинками. Повторный запуск ничего не дублирует.
6. Настройки → Постоянные ссылки → Сохранить (обновит правила ссылок).

### Почему ключ в wp-config, а не в админке

Ключ даёт полный доступ к CRM: ученики, телефоны, платежи. В `wp-config.php`
он не попадает в дамп базы, в резервную копию контента и в репозиторий.
Вариант с полем в админке тоже поддержан (`map_mk_api_key`), но экран
настроек про него предупреждает.

Если править `wp-config.php` неудобно, можно положить
`inc/config.local.php` с тем же `define()` — файл в `.gitignore`.

## Структура

```
functions.php          только константы и подключение inc.php
inc.php                загрузчик модулей в порядке зависимостей
inc/
  config.php           реквизиты и значения по умолчанию
  icons.php            SVG-иконки (генерируется, править генератор)
  icons-custom.php     иконки из медиатеки: чистка и перекраска SVG
  helpers.php          map_opt(), map_socials(), map_cta_attrs()
  nav.php              меню шапки и подвала, обходчики
  template-tags.php    карточки, слайдеры, секции
  setup.php            возможности темы, меню, размеры картинок
  performance.php      чистка лишнего, ресурсные подсказки, defer
  assets.php           подключение CSS/JS, предзагрузка шрифтов
  post-types.php       педагоги, направления, отзывы, мастера, заявки
  acf.php              настройка ACF, страница опций, синхронизация групп
  hardening.php        закрытие лишней информации о сайте
  moyklass.php         клиент API CRM
  rest.php             маршруты /wp-json/map/v1/
  booking.php          приём заявки, антиспам, повторная отправка
  slots.php            свободные окна педагогов из CRM
  notify.php           уведомления о заявке: почта и Telegram
  admin.php            экран интеграции, карточка заявки
  seed.php             первичное наполнение контентом

template-parts/
  home/                секции главной
  page/hero.php        первый экран внутренних страниц
  modal/               окна записи, педагога и видео

assets/                CSS, JS, шрифты, изображения, Swiper
seed/content.json      контент для первичного наполнения
```

Правило: `functions.php` не растёт. Новая логика — новый файл в `inc/`
и строка в списке модулей `inc.php`.

### Что редактируется из админки

Общее для всего сайта — в разделе **Настройки сайта**, по вкладкам:
логотип (светлый и тёмный вариант, значок вкладки), контакты, соцсети,
подписи колонок подвала и копирайт, надписи на кнопках записи, тексты окна
записи, блок расписания «Мой класс», уведомления о заявках (почта и
Telegram), страница 404 и тексты пустого поиска.

Всё, что принадлежит конкретной странице, — в её же карточке, тоже по
вкладкам. У главной вкладка на каждый блок: первый экран, о центре, новости,
направления, педагоги, видео, разделители, отзывы, как нас найти, призыв к
записи. У страниц «О нас», «Наши направления», «Педагоги» и «Новости» —
тоже по вкладке на блок: первый экран, заголовки секций, списки (особые
программы, принципы методики, вопросы и ответы, фотогалерея) и призыв
к записи.

Пустое поле не ломает страницу: шаблон подставит прежний текст. Поэтому
удалить значение безопасно — вернётся то, что было до правки.

Служебные подписи интерфейса («Читать», «Все новости», «Закрыть», подписи для
скринридера) остались в коде намеренно: выносить их в настройки — значит
сделать настройки нечитаемыми ради того, что никто не меняет.

Набор полей описан в `tools/build-theme-fields.py`. Скрипт только дополняет
файлы `acf-json` и не трогает то, что уже есть, — его можно запускать
повторно и после правок из админки.

### Цифры, которые считаются сами

Блок с цифрами на главной («12 педагогов и приглашённых артистов») и такой же
на странице «О нас» больше не набирают руками. В каждой строке есть колонка
**«Что считать»**: выберите «Педагоги и приглашённые мастера» — и число
возьмётся из количества опубликованных карточек. Считать можно педагогов,
приглашённых мастеров, их сумму, направления, отзывы и новости.

Черновики и записи в корзине не в счёт — только опубликованные. Колонка
«Приписка» дописывает к посчитанному числу знак вроде `+`.

Строку можно оставить и на ручном числе: пустое «Что считать» — и показывается
то, что вписано в колонку «Число». Так сделаны «3+ возраст первых занятий» и
«∞ взрослые любого возраста»: считать там нечего. Ручное число служит и
запасным вариантом — если считать нечего (раздел ещё не наполнили), сайт
покажет его вместо нуля.

На сайтах, наполненных раньше, строки про педагогов, направления и отзывы
переводятся на подсчёт один раз сами — при первом заходе в админку
(`map_upgrade_fact_sources()` в `inc/seed.php`).

### Группы полей

Лежат в `acf-json/` — по файлу на группу. Их можно свободно править через
админку: ACF при каждом сохранении переписывает файл, поэтому изменение
попадает в репозиторий вместе с темой и переезжает на другие копии сайта.

На копии, где групп ещё нет в базе (свежая установка, перенос на хостинг),
они подхватываются из файлов при первом заходе в админку — см.
`map_acf_sync_json()` в `inc/acf.php`. Нажимать «Синхронизировать» вручную
не нужно.

### Значок вкладки

Задаётся в **Настройки сайта → Логотип → Значок вкладки**. Поле заодно
проставляет стандартный «Значок сайта» WordPress и готовит нарезку размеров,
поэтому иконка появляется и на самом сайте, и в админке, и на экране входа —
менять её в двух местах не нужно. Если поле пустое, берётся
`assets/img/ui/favicon.png` из темы: вкладка с чужим глобусом выглядит хуже
любой картинки.

Картинка должна быть квадратной и не меньше 512×512 — из неё WordPress
нарезает всё остальное, вплоть до плитки приложения.

### Иконки

Иконка — обычная картинка из медиатеки: её выбирают полем рядом с текстом,
как фотографию. Так сделано везде, где иконка видна: в направлении,
в особых программах и принципах методики, в надглавии первого экрана
и в списке преимуществ на главной.

Готовый набор темы лежит файлами в `assets/img/icons` и попадает
в медиатеку при наполнении — файлы собираются из вёрстки командой
`python3 tools/build-icon-files.py`. Заменить любую иконку на свою можно,
не трогая код: загрузить SVG в поле.

Чтобы чужой файл вставал в тему без правок, при выводе с ним делается три
вещи:

- **чистка.** SVG вставляется в страницу разметкой, иначе он не подхватит
  цвет темы. Поэтому файл проходит через белый список тегов и атрибутов:
  скрипты, обработчики событий, внешние ссылки и картинки вырезаются.
  Загружать SVG может только администратор.
- **перекраска.** Наборы вроде Flaticon отдают файл с зашитым чёрным.
  Если цвет в файле один, он заменяется на `currentColor` и иконка берёт
  цвет темы. Если цветов несколько, это уже рисунок, а не значок — такой
  остаётся как есть.
- **заливка.** Гнёзда иконок задают обводку правилом CSS, а правило сильнее
  атрибута — сплошная иконка от него превратилась бы в контур. Поэтому
  заливка и обводка корня переносятся в inline-стиль: файл решает сам.
  Файл, не сказавший ничего, считается сплошным.

- **пространство имён.** Внутри страницы его подставляет разборщик HTML,
  а отдельный файл без `xmlns` не откроется вовсе — ни в `<img>`,
  ни предпросмотром. Поэтому атрибут дописывается, если его нет.

Размеры векторного файла WordPress читать не умеет и пишет в метаданные
пустоту, из-за чего сам же рисует превью в один пиксель. Тема читает размер
из `width`/`height` или `viewBox` и отдаёт медиатеке набор размеров —
иначе в поле была бы пустая серая рамка вместо иконки.

Результат чистки кэшируется в мета-поле вложения и пересобирается только
после замены файла. Пустое поле не ломает страницу: шаблон подставит
иконку из кода темы.

### Шаблоны страниц

«О нас», «Наши направления» и «Педагоги» — обычные страницы с выбранным
шаблоном (Свойства страницы → Шаблон). Тема находит их по шаблону, поэтому
адрес и заголовок можно менять свободно.

## Онлайн-запись

```
форма на сайте
   ↓ POST /wp-json/map/v1/booking
проверки: ловушка для ботов, таймер, лимит по адресу, валидация
   ↓
запись «Заявка» в WordPress          ← сохраняется всегда
   ↓
POST /v1/company/users в «Мой класс» ← карточка ученика
POST /v1/company/userComments        ← заметка: направление, педагог, страница
   ↓
письмо на почту центра + сообщение в Telegram
```

Ключ API в браузер не попадает: страница обращается только к своему сайту.

**Если CRM недоступна.** Посетитель всё равно видит подтверждение, заявка
получает статус «Ждёт отправки», и WordPress повторяет попытку по расписанию
(через 15 минут, дальше раз в час, максимум 10 попыток). Досылку можно
запустить руками кнопкой «Дослать заявки».

**После отправки** форма пропадает: на её месте — подтверждение с галочкой,
а через пару секунд окно закрывается само. Пустые поля рядом с «спасибо»
сбивают с толку, а искать крестик после отправки посетителю незачем. Текст
подтверждения — «Настройки сайта → Форма записи → Сообщение после отправки».

**Защита от спама** — без капчи: скрытое поле-ловушка, минимальное время
заполнения формы, не более 5 заявок в час с одного адреса.

**Согласие на обработку данных** проверяется на сервере, а не только галочкой
в браузере: запрос без него отклоняется. Факт согласия пишется в карточку
заявки — время, адрес посетителя, страница и действующая политика.

⚠️ **Перед запуском опубликуйте политику конфиденциальности.** Пока страницы
нет, ссылка на неё не выводится, а собирать персональные данные без
опубликованной политики нельзя. Страница задаётся в Настройки → Приватность.

**Повторов не будет.** Перед созданием карточки сайт ищет ученика по телефону:
если «Мой класс» принял заявку, но ответ не дошёл за отведённое время,
повторная отправка не создаст второго ученика, а допишет комментарий.

**Формат телефона.** CRM принимает только цифры (`^[0-9]{10,15}$`).
Тема приводит любой ввод к `+7XXXXXXXXXX` для сайта и снимает плюс при
отправке в CRM.

### Свободные окна педагогов

В карточке педагога вместо расписания, набитого руками, показывается реальное
свободное время из «Моего класса»: дни сверху, время выбранного дня под ними.
Клик по времени открывает форму записи с подставленным «Выбранное время» —
оно уходит и в письмо, и в Telegram, и в заметку к ученику в CRM.

**Откуда берётся.** Прямого маршрута со свободным временем в API компании нет:
`/v1/user/managers/individualLessons` живёт в личном кабинете ученика и ключ
компании туда не пускает (401). Зато доступны `busyTimes` — нерабочее время
педагога — и `lessons` — его занятия. Из них окно и складывается:

```
рабочий день центра − нерабочее время педагога − его занятия
```

⚠️ **Рабочий день задаётся в настройках сайта**, а не берётся из CRM: часы
работы компании наружу не отдаются. «Настройки сайта → Свободные окна» —
там же длительность занятия, глубина показа и запас времени, ближе которого
окна на сегодня не предлагаются. Если в CRM поменяли часы работы центра,
их нужно поменять и здесь, иначе сайт покажет чужое время.

**Педагог ищется по имени.** Если имя в CRM и на сайте совпадает, ничего
настраивать не нужно. Не совпадает — впишите номер в карточке педагога, поле
«ID педагога в «Моём классе»» на вкладке «Расписание».

**Когда окон нет**, карточка говорит об этом словами, а не показывает пустоту:

| Что случилось | Что видит посетитель |
|---|---|
| Есть свободное время | дни и время, кликом открывается форма записи |
| Педагог есть в CRM, окон нет | «На ближайшие дни свободного времени нет…» |
| Педагога в CRM не нашли | «Время для записи к этому педагогу пока не добавлено…» |
| CRM не ответила | расписание, заполненное руками в карточке |

Оба текста меняются в настройках. Разделение важное: «всё занято» и «время ещё
не завели» — разные вещи, и заказчику по второму тексту сразу видно, кому в CRM
не задали рабочее время.

Показать занятое время как свободное хуже, чем не показать ничего, — поэтому
при молчании CRM окна не выводятся вовсе.

Окна приезжают отдельным запросом: страница может быть отдана из кэша, а
расписание меняется в течение дня. Запрос уходит один на всю страницу и сразу
после её загрузки (`GET /wp-json/map/v1/slots` — окна всех педагогов, около
10 КБ), поэтому к первому клику данные уже на руках и карточка открывается
с готовой таблицей. Если ответ почему-то задержался, в карточке сначала
покажется расписание из админки, а окна встанут на его место, когда приедут.
Есть и адрес для одного педагога — `?teacher=ID`. Ответы CRM кэшируются
на 15 минут.

### Уведомления о заявках

Заявка уходит тремя путями сразу: в CRM, письмом и в Telegram. Настраивается
всё в **Настройки сайта → Уведомления о заявках**.

**Почта.** Основной адрес — `musicartplus@yandex.ru`; в поле «Копии на другие
адреса» можно дописать ещё несколько через запятую. Если поля пустые, письмо
уходит администратору сайта: потерять заявку хуже, чем прислать её не тому.

⚠️ Письма отправляет сам сервер, и почтовые службы такие письма нередко
кладут в спам. На боевом сайте нужен плагин SMTP с почтовым ящиком центра —
без него доставка не гарантирована. Отметка «Письмо: сервер не принял письмо»
в карточке заявки как раз про это.

**Telegram.** Нужен свой бот: напишите `@BotFather`, команда `/newbot` — он
выдаст токен вида `123456789:AA…`. Токен впишите в поле «Токен бота» или,
надёжнее, в `wp-config.php` константой `MAP_TG_BOT_TOKEN` — тогда он не
попадёт в дамп базы.

Чатов может быть сколько угодно — заявка уйдёт в каждый. ID чата: для личного
сообщения его подскажет бот `@userinfobot`, для группы — добавьте туда своего
бота и откройте `api.telegram.org/bot‹токен›/getUpdates`. У групп и каналов ID
начинается с минуса. Бот должен состоять в группе, иначе Telegram ответит
отказом.

Кнопка **«Проверить Telegram»** на экране «Интеграция с CRM» шлёт пробное
сообщение во все чаты и показывает, какой из них не ответил.

Если чат недоступен, сайт запоминает, куда сообщение уже ушло, и через десять
минут досылает только в оставшиеся — двух одинаковых сообщений в рабочем чате
не будет. После восьми неудач попытки прекращаются, а в карточке заявки
остаётся ответ Telegram. Токен в сообщениях об ошибке заменяется многоточием.

### Маршруты

| Маршрут | Что делает |
|---|---|
| `POST /wp-json/map/v1/booking` | принимает заявку |
| `GET /wp-json/map/v1/schedule` | публичное расписание групп из CRM |
| `GET /wp-json/map/v1/slots` | свободные окна педагога (только время) |

`schedule` отдаёт только название группы, программу, педагога и цену.
Данные учеников наружу не выходят.

### Кэш

Ответы CRM кэшируются: справочники — 6 часов, группы — час, расписание —
15 минут. Токен доступа живёт 7 дней, хранится 6. Кнопка «Сбросить кэш CRM»
на экране интеграции чистит всё сразу.

## Защита

Модуль `inc/hardening.php` закрывает то, что WordPress по умолчанию отдаёт всем:

- **XML-RPC** отключён полностью. Фильтра `xmlrpc_enabled` мало — он снимает
  только методы со входом, а `pingback.ping` и `system.multicall` остаются
  и используются для усиления атак на чужие сайты.
  Вернуть: `add_filter( 'map_allow_xmlrpc', '__return_true' );`
- **Перечисление пользователей.** Адрес `/?author=1` больше не переадресует
  на `/author/логин/`, а маршрут `/wp-json/wp/v2/users` закрыт для всех,
  кроме тех, кто и так видит список пользователей в админке.
- **Версия ядра** убрана из адресов стилей и скриптов — по ней подбирают
  известные уязвимости.
- **Сообщение при неудачном входе** одинаковое для неверного логина
  и неверного пароля.

Что осталось за пределами темы и делается настройкой сервера: закрыть
`readme.html`, `license.txt`, файлы журналов и запретить выполнение PHP
в папке загрузок.

## Быстрая загрузка

Что сделано и зачем:

- **Шрифты локальные.** Убраны обращения к `fonts.googleapis.com` и
  `fonts.gstatic.com` — это два лишних DNS-резолва и два TLS-хендшейка перед
  первой отрисовкой текста. Скачаны только кириллица и латиница.
- **Предзагрузка двух основных начертаний** — заголовок первого экрана
  не успевает мигнуть системным шрифтом.
- **Первая картинка первого экрана** грузится с `fetchpriority="high"`,
  остальные — лениво. Ленивая загрузка LCP-картинки ухудшает показатель.
- **Без jQuery.** На фронтенде только свой скрипт и Swiper.
- **Swiper подключается только там, где есть слайдеры** (~140 КБ).
- **Отключены** скрипт эмодзи, wp-embed, стили редактора блоков и
  встроенные глобальные стили (~9 КБ на каждой странице).
- **Все скрипты с `defer`.**
- **Версии файлов** — по времени изменения: кэш сбрасывается сам.
- **Ответы CRM кэшируются**, чтобы страница не ждала внешний сервис.

Итого на главной: 3 файла CSS, 2 файла JS плюс скрипт виджета.

## Сборка вспомогательных файлов

Иконки и контент для наполнения генерируются из вёрстки, чтобы не
расходились. После правки `tools/generator.py`:

```bash
python3 tools/build-theme-icons.py   # inc/icons.php
python3 tools/build-theme-seed.py    # seed/content.json
python3 tools/build-theme-fonts.py   # assets/fonts/ и assets/css/fonts.css
python3 tools/sync-theme-assets.py   # картинки, видео, Swiper из вёрстки
```

**CSS и JS темы живут своей жизнью.** В них добавлено то, чего нет в статике:
служебные классы WordPress, постраничная навигация, отправка формы на
REST-маршрут. Скрипт синхронизации их намеренно не трогает — после переезда
на WordPress стили и скрипты правятся в теме, статическая вёрстка остаётся
слепком дизайна на момент согласования.

## Известные ограничения

- **Своих страниц у педагогов и направлений нет.** Карточка педагога
  открывается модальным окном, направление — якорем на общей странице.
  Типы записей закрыты от фронтенда, старые адреса `/pedagogi/…`
  и `/napravleniya/…` переадресуются на списки.
- Тема проверена на **ACF PRO 6.8.3**. На старой 6.0.2 она тоже работает,
  но та версия на PHP 8.x засыпает журнал предупреждениями `Deprecated` —
  ставьте актуальную.
- Для писем о заявках нужен рабочий `wp_mail`. На большинстве хостингов
  почта уходит в спам — лучше поставить SMTP-плагин.
- Повторная отправка заявок держится на `wp-cron`. Если он отключён,
  подключите системный cron или пользуйтесь кнопкой «Дослать заявки».
